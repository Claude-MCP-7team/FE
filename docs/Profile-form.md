# M1 사용자 입력 폼 · FE 초안

브랜치: `feat/profile-form` → `dev`. Final MVP 문서 반영 PR과 독립적으로 검토한다.

## 실행 및 범위

- 기존 디자인: `npm.cmd run preview` → http://127.0.0.1:4173 → 조건 수정 또는 프로필 버튼 → `/profile.html`
- M0 앱: `npm.cmd run dev` → http://127.0.0.1:5173/#/profile
- 같은 폼 컴포넌트·검증기를 두 진입점에서 사용한다. 프로토타입의 기존 입력 모달과 가짜 저장/재분석 동작을 대체한다.
- 이 탭의 sessionStorage 임시 보관·조회·수정 취소·삭제를 지원한다. 두 포트는 서로 다른 origin이므로 임시 조건을 공유하지 않는다.
- 서버 저장·AI/BE 재판정은 수행하지 않는다. 정책 결과는 기존 고정 예시이며 입력값에 따라 바뀌지 않는다.

## 입력 및 검증 초안

생년월일·거주지역·연속 거주 시작일을 필수로 제안한다. 날짜는 실제 달력 날짜, 오늘 이하, 거주 시작일은 출생일 이상인지 확인한다. 연령이나 거주기간의 정책 자격 여부를 FE가 판정하지 않는다.

소득은 0 이상 안전한 정수, 가구원 수는 1 이상 안전한 정수다. 모르는 값은 null이며 소득 0원과 다르다. 잘못된 선택지 값을 거부한다. 필드별 오류, 요약 오류와 입력 위치 이동, 저장 실패 안내를 제공한다.

필드 이름은 Final MVP의 personal_income, employment_type, household_size를 따른다. 이름·주민등록번호·상세주소는 수집하지 않는다. received_policy_ids와 answers는 목록/질문 API 연결 전이므로 임의 생성하거나 수집하지 않는다.

## Issue #2에서 합의 필요

필수 여부·enum·지역 코드·소득 월/연 기준은 FE 편집용 초안이다. 지역의 `gyeonggi-other`는 확정 시군구 코드가 아니다. Profile API 연결 시 BE 스키마에 맞춰 선택지 및 직렬화를 교체해야 한다. 임시 저장값을 현재 상태 그대로 API로 전송하지 않는다.

## 검증

`npm.cmd test`: 필수값, 달력·윤년·미래 날짜, 숫자 경계, 0/null, 선택지, 임시 보관/편집/삭제, 저장 실패·손상 데이터, 두 서버 자산 허용 범위를 검증한다.

브라우저 수동 확인 순서: 빈 폼 제출 → 요약 오류 링크로 필드 이동 → 조건 입력/임시 보관 → 새로고침 → 수정/취소 → 임시 조건 삭제 취소/확인 → 모바일 너비 및 키보드 확인.

실제 서버 저장과 M1 전체 완료 판정은 별도 API 연동 PR 및 E2E 통과 후 처리한다.
