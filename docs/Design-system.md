## 1. 【D-1】 팔레트가 두 벌이다

현재 저장소에는 **서로 무관한 색 체계 두 개**가 공존한다. 사용자는 같은 서비스 안에서 화면을 이동하는데, 프로필 화면만 다른 제품처럼 보인다.

| | `src/styles.css` (결과·상세·조합·일정) | `src/profile.css` (프로필 입력) |
| --- | --- | --- |
| 계열 | 녹색 + 따뜻한 중성색 | 파랑 + slate 중성색 |
| 주조색 | `#135f3c` 짙은 녹색 | `#5B8DEF` 밝은 파랑 |
| 강조/링크 | `#135f3c` | `#3059A6` |
| 페이지 배경 | `#f5f7f3` (녹빛 오프화이트) | `#F8FAFC` (푸른빛 오프화이트) |
| 본문 글자 | `#17221c` | `#1E293B` |
| 보조 글자 | `#59675f` | `#64748B` |
| 경계선 | `#dfe5df` | `#E2E8F0` |
| 라운드 (카드) | 20px | 18px |
| 라운드 (버튼) | 12px | 10px |
| 라운드 (입력) | 8px | 10px |
| 버튼 최소 높이 | 미지정 | 44px |
| 반응형 분기점 | 700px | 650px |
| 클래스 접두사 | 없음 | `.pf-` |

### 선택지

- **선택지 A — 녹색(`styles.css`)으로 통일.** 프로필 화면을 녹색 체계로 옮긴다.
  - 장점: 화면 수가 많은 쪽(결과·상세·질문·조합·일정 5개)이 기준이 되므로 수정 범위가 작다. 브랜드색이 하나로 선다.
  - 단점: `profile.css`의 44px 터치 타깃, `aria-invalid` 처리 등 더 다듬어진 부분을 옮겨와야 한다.
- **선택지 B — 파랑(`profile.css`)으로 통일.**
  - 장점: 입력 폼 쪽이 접근성·상태 처리가 더 갖춰져 있다.
  - 단점: 5개 화면을 모두 고쳐야 한다. `FUTURE_PASS`의 파랑(`#325975`)과 주조색이 충돌해 상태색을 다시 잡아야 한다.
- **선택지 C — 유지.** 프로필을 의도적으로 다른 맥락으로 둔다.
  - 단점: 권장하지 않는다. Milestone 인터페이스 4번이 막으려던 상황이다.

## 6. 접근성 기준

### 지켜야 할 것

- 본문 글자 대비 **4.5:1** 이상
- **UI 컴포넌트의 경계** — 입력창, 버튼처럼 그 테두리가 요소를 식별하는 유일한 수단인 경우 **3:1** 이상
  (카드 테두리·구분선은 장식이므로 이 요구가 적용되지 않는다)
- 상태를 색만으로 전달하지 않는다 → 배지는 색 + 기호 + 문구 3중으로 제공 (현재 준수)
- 포커스 표시를 제거하지 않는다 → `:focus-visible` 아웃라인 3px 유지 (현재 준수)
- 터치 타깃 44px 이상

## 7. 적용된 수정 (2026-09-19)

접근성 미달 4건을 고쳤다. **색 체계는 바꾸지 않았고, 대비가 부족한 경계선만 올렸다.**

| 파일 | 대상 | 변경 | 결과 |
| --- | --- | --- | --- |
| `src/styles.css` | `input`, `select` 테두리 | `#a8b7ad` → `#7d8f84` | 2.09 → 3.42 |
| `src/styles.css` | `button`, `.button` 테두리 | `--line` → `--line-strong` | 1.28 → 3.42 |
| `src/profile.css` | `.pf-field input/select` 테두리 | `#CBD5E1` → `#7E8DA3` | 1.48 → 3.37 |
| `src/profile.css` | `.pf-page button` 테두리 | `#E2E8F0` → `#7E8DA3` | 1.23 → 3.37 |

카드 테두리·구분선·`fieldset` 테두리는 **장식 요소이므로 그대로 두었다.** 이를 함께 올리면 화면이 과하게 선으로 나뉜다.

`--line-strong` 토큰을 새로 정의했으므로, 앞으로 **테두리가 요소를 식별하는 유일한 수단인 경우** 이 토큰을 쓴다.

## 8. 스타일이 없는 클래스

`dev`가 판정·역질문·조합 화면을 연결하면서 추가한 아래 클래스에 **CSS 규칙이 없다.**
마크업에만 존재하고 아무 스타일도 적용되지 않는다.

| 클래스 | 쓰이는 곳 | 시각적 구분이 필요한가 |
| --- | --- | --- |
| `.judgement-summary` | Dashboard 요약 | 공통 `.summary`로 충분해 보임 |
| `.judgement-card` | 정책 카드 | 공통 `.card`로 충분해 보임 |
| `.question-card` | 역질문 카드 | 공통 `.card`로 충분해 보임 |
| ~~`.conflict`~~ | 조합에서 제외된 정책의 충돌 표시 | **정의함** (2026-09-19) |
| ~~`.notice-inline`~~ | 담당부서 확인 안내 | **정의함** — S-4와 함께 처리 |

`.notice-inline`과 `.conflict`는 정의했다. 나머지 셋은 공통 클래스로 형태가 잡히므로 제거해도 되지만, 앞으로 화면별 조정이 필요할 수 있어 판단을 보류한다.

이 문서는 색·형태 토큰만 다루므로, 새 스타일을 정의할 때도 2~4장의 토큰 안에서 조합한다.

## 9. 신뢰도 칩 (S-4)

판정 상태 배지와 **형태로도 구분**되도록 정의했다. 배지는 채워진 알약, 칩은 비어 있는 알약이다.

| | `.badge` (판정 상태) | `.chip` (신뢰도) |
| --- | --- | --- |
| 배경 | 상태색으로 채움 | 없음 |
| 테두리 | 없음 | 1px `var(--line-strong)` |
| 글자 | 상태색 (짙은 쪽) | `#4f5c54` |
| 굵기 | 700 | 600 |
| 라운드 | 24px | 24px |

**판정 상태 4색은 판정 상태만 뜻한다.** 신뢰도·조합·서류 등 다른 축에 이 색을 쓰지 않는다.

대비: 칩 글자 7.02(흰 배경) / 6.51(페이지 배경), 테두리 3.42 / 3.18. 모두 기준을 넘는다.

칩은 `src/confidence.js` 한 곳에만 정의한다. 판정 화면과 조합 화면이 같은 모듈을 쓰므로 문구가 화면마다 갈라지지 않는다.

## 11. 제외된 정책 블록 (`.conflict`)

조합에서 제외된 정책의 사유를 담는다. 여러 개가 `<details>` 안에 쌓인다.

| 항목 | 값 |
| --- | --- |
| 배경 | `var(--bg)` — 흰 카드 위에서 한 단 들어가 보인다 |
| 테두리 | 1px `var(--line)` + 좌측 3px `var(--line-strong)` |
| 라운드 | 12px |
| 안쪽 여백 | 14px 16px |
| 블록 간격 | 12px |

**상태색을 쓰지 않는다.** 제외는 판정이 아니다. 여기에 `FAIL` 빨강을 쓰면 "부적격 판정"으로 읽혀, 신뢰도에 `UNKNOWN` 노랑을 썼던 것과 같은 실수가 된다. 좌측 굵은 선은 인용 블록(`blockquote`)과 같은 어법이되 색만 중성이다.

안에 들어가는 순서는 **정책명 → (신뢰도 칩) → 우리가 쓴 사유 → 원문 인용**이다.
인용 블록은 `.conflict`의 `--bg` 위에서 다시 흰 배경을 써서 한 겹 더 구분된다.

`<details><summary>`에도 최소한의 클릭 가능 표시(커서·굵기)를 넣었다. 그 전에는 일반 본문처럼 보였다.
