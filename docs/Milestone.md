# 1. 제출 성공 기준

제출 버전에서는 아래 핵심 흐름이 한 번에 연결되어야 한다.

```
사용자 조건 입력
→ 정책 조회
→ AI 공고문 분석·구조화
→ BE 룰 엔진 자격 판정
→ 부족 정보 AI 역질문
→ 답변 저장·재판정
→ 판정 근거·향후 가능 시점
→ AI가 중복수혜 관계 추출
→ BE가 가능한 정책 조합 계산
→ 필요서류·신청 일정
```

## 역할 경계 핵심 원칙

<aside>
🔒

**AI는 공고문을 이해하고 구조화하며 질문과 설명을 만든다.**  

**Backend는 판정·날짜 계산·정책 조합처럼 결과가 항상 같아야 하는 결정론 로직을 담당한다.**  

**Frontend는 이 결과를 사용자가 이해하고 행동할 수 있게 보여준다.**

</aside>

### 🤖 AI 담당

- 공고문 Parsing 및 조건 구조화
- 자격/제외/서류/마감/중복수혜 문구 추출
- Source Evidence 연결
- UNKNOWN 원인 분석 및 역질문 생성
- 판정 결과 설명문 생성
- 중복수혜 상충 관계 추출
- 필요서류명 정규화 보조
- 교차검증 및 Hallucination 점검

### 🛠️ Backend 담당

- UserProfile / Policy / PolicyCondition DB 및 API
- 결정론적 Eligibility Rule Engine
- PASS / FAIL / UNKNOWN / FUTURE_PASS 최종 판정
- 향후 충족일 계산
- 답변 기반 재판정 Pipeline
- 중복수혜 Conflict Matrix 및 조합 계산
- 필요서류·발급기간·신청일정 역산
- API, 저장, 로그, 예외처리

### 💻 Frontend 담당

- 사용자 조건 입력/수정
- 분석 진행 상태
- 결과 Dashboard / 정책 상세
- 판정 이유·근거·향후 가능 시점
- AI 역질문 UI
- 정책 조합 추천 UI
- 필요서류 Checklist / 신청 Timeline
- Loading / Error / Empty / 반응형

### 🎨 Design · Planning 지원

- 핵심 화면 IA 및 상태 정의
- PASS / FAIL / UNKNOWN / FUTURE_PASS 표현 규칙
- 디자인 시스템과 핵심 화면 시안 선행 제공
- 판정 근거/신뢰도/면책 문구 검수
- 발표 시나리오와 제출 자료 정리

# 10. 파트별 최종 책임

| 파트 | 최종 책임 | 하지 않는 것 |
| --- | --- | --- |
| **AI** | 공고문 해석·구조화, 근거, 역질문, 설명, 상충관계 추출, 교차검증 | 최종 판정 Rule, 조합 Solver, 날짜 산술 |
| **Backend** | DB/API, Rule Engine, FUTURE_PASS 계산, 재판정, Conflict/조합 계산, 일정 역산 | Prompt 설계, 화면 UI |
| **Frontend** | 입력, 결과, 상세, 역질문, 조합, 서류·일정 UI, API 연동 | 자격 판정 비즈니스 로직 |
| **Design·Planning** | IA, 디자인 시스템, 판정 표현 규칙, 카피, QA, 발표 시나리오 | 판정/조합 구현 코드 |

# 11. 반드시 고정할 인터페이스 4개

1. **AI ↔ BE: PolicySchema / PolicyCondition** — AI가 채우고 BE가 읽는다.
2. **BE ↔ FE: JudgementResult** — FE는 판정 로직을 추측하지 않고 Response만 표현한다.
3. **AI ↔ BE: ConflictRelation** — AI는 상충 관계와 원문 근거만 반환하고 BE가 조합을 계산한다.
4. **Design ↔ FE: 상태·근거 표현 규격** — 판정 상태와 근거 UI를 화면마다 다르게 만들지 않는다.

<aside>
🔴

**가장 중요한 품질 기준:** 모든 판정 결과는 원문 Evidence와 연결되어야 한다. 원문 근거가 없는 조건은 자동 확정하지 않고 UNKNOWN 또는 추가 확인으로 처리한다.

</aside>

# 12. 일정이 밀릴 때 줄이는 순서

1. 추가 지역·정책 범위 확대 중단
2. 고급 필터/정렬 제거
3. 조합 비교 2안 이상 제거 → 추천 조합 1안만 유지
4. 고급 최적화 Solver 제거 → P0 단순 조합 계산 유지
5. 세부 Animation/통계 제거
6. 관리자 검증 화면 제거

**절대 줄이지 않는 핵심:**

```
실제 공고문
→ 구조화
→ 결정론 자격 판정
→ 근거
→ 역질문·재판정
→ 중복수혜 관계
→ 정책 조합
→ 신청 서류·일정
```

# 13. 매일 진행 상태 기록 규칙

매일 작업 종료 전에 각 파트는 아래 4개만 기록한다.

- **완료:** 오늘 실제 완료 판정을 통과한 것
- **다음:** 내일 가장 먼저 처리할 1~2개
- **막힌 점:** 다른 파트 응답/데이터가 필요한 것
- **결정 필요:** 팀 전체가 결정해야 하는 것
