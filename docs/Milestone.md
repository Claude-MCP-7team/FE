## 1. 제출 성공 기준

제출 버전에서는 아래 핵심 흐름이 한 번에 연결되어야 한다.

```
사용자 조건 입력
→ 정책 조회
→ AI 공고문 분석
→ 자격 판정
→ 부족 정보 역질문
→ 재판정
→ 판정 근거·향후 가능 시점
→ 중복수혜 분석
→ 최적 정책 조합
→ 필요서류·신청 일정
```

### P0 — 반드시 제출할 기능

- 사용자 기본조건 입력 및 수정
- 정책 데이터 조회
- 공고문 기반 자격조건 구조화
- PASS / FAIL / UNKNOWN / FUTURE_PASS 판정
- 판정 이유 및 근거 표시
- AI 역질문 및 재판정
- 최소 1개 시나리오의 중복수혜 분석
- 필요서류 및 신청 일정 표시

### P1 — 시간이 남을 때만

- 고급 필터/정렬
- 조합 비교 옵션 확장
- 세부 애니메이션
- 부가 통계
- 추가 지역/정책 범위 확대

# 10. 매일 진행 상태 기록 규칙

매일 작업 종료 전에 각 파트가 아래 네 줄만 남긴다.

- **완료:** 오늘 실제로 완료 판정된 것
- **다음:** 내일 가장 먼저 할 1~2개 작업
- **막힌 점:** 다른 파트 응답이나 데이터가 필요한 것
- **결정 필요:** 팀 전체가 결정해야 하는 것

<aside>
✅

체크리스트는 **코드를 작성했다는 이유가 아니라 실제 완료 판정을 통과했을 때만 체크**한다. 일정이 밀리면 P1과 화면 장식을 줄이고, 자격 판정 → 역질문 → 조합 → 신청 일정의 핵심 흐름은 유지한다.

</aside>
