# Frontend 진행 기록

## 2026-09-17 · PR #8 재마운트 리뷰 반영

- **완료:** 프로필 화면의 빠른 재진입이 진행 중인 조회를 공유하도록 수정. 저장·삭제 중 재진입은 요청 종료 후 새로 조회. 실제 조회 실패는 오류 및 재시도 UI로 전달.
- **검증:** 실제 mountProfile 함수를 DOM 대역으로 실행하는 재마운트·실제 실패/재시도 테스트와 저장·삭제 대기 테스트 추가. 전체 50개 테스트 및 문법 검사 통과. 실제 브라우저 검증을 대체하지 않음.

## 2026-09-17 · 프로필 폼 서버 연결

- **완료:** PR #7 병합 확인. `YPC_API_BASE` 설정 시 두 프로필 진입점에서 서버 조회·생성·수정·삭제 사용. 조회 실패 재시도, 중복 요청 차단, 저장 실패 시 입력 보존, 삭제 확인 및 재시도 구현.
- **데이터 보존:** 전체 교체 PUT에 대비해 폼에서 변경한 필드만 갱신하고 기존 core 추가 필드·history·answers·consent 보존. 편집 불가능한 기존 enum/지역 값은 유지 옵션으로 표시. 미지원 입력은 전송 전 차단.
- **검증:** 단위 테스트 및 임시 로컬 HTTP 서버를 통한 생성→조회→수정→삭제 검증. 연결 가능한 브라우저와 실제 BE 주소가 없어 브라우저/CORS/운영 서버 E2E는 미수행.
- **다음:** 소득·선택지·지역 코드 계약과 동의 수집 확정, 실제 BE 연결 검증 후 M1 완료 판정. 정책 판정 API는 아직 Mock 상태.

## 2026-09-16 · Profile API 오류 처리 보강

- **완료:** 삭제 실패 시 세션 ID를 보존해 재시도 가능하도록 수정. 삭제 404는 이미 삭제된 상태로 처리. 조회 응답의 profile 누락·잘못된 타입·손상된 JSON을 오류로 구분하고 본문 수신 실패를 네트워크 오류로 정규화.
- **검증:** `npm.cmd test` 36개 통과, `npm.cmd run check` 통과. 실제 BE 통합 및 브라우저 검증은 수행하지 않음.
- **다음:** 폼의 미지원 입력값과 BE 필드 매핑을 확정한 뒤 서버 조회·저장·삭제 UI 연결. PUT은 전체 교체이므로 기존 answers/history/consent 및 폼에 없는 core 필드를 보존해야 함.
- **남은 조건:** 실제 API 주소 및 미지원 필드 계약 확정. M1 전체 완료는 서버 연결 E2E 검증 후 판단.
